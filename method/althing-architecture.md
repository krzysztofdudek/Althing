# Althing's architecture

The decision record of this repository: how it is organised and policed, and why. Each section is a choice and its reason. What each rail catches and how to fix a refusal is in [the rails' README](../rails/README.md); where a thing lands is the placement table in section 5 of `AGENTS.md`; what never enters, and what to do when something does, is [the boundary](boundary.md).

## The decision

On 2026-10-05 the owner made Althing the family's layer above its tools: public, everything in it English, everything committed on purpose (`althing-family-layer`). It holds the thesis, the canon, the method, the standing rulings, every release loop from 6.2.0 on, the research, the triage of reports for every tool, and the workspace that checks a release's exact commits against each other. The tools' code stays in the tools' repositories. An agent started here needs nothing from anywhere else.

Three consequences shape everything below:

- **Public by design.** Anything committed is published. The gate's first job is to keep out what must never be published, and to do it before a push, not after.
- **Self-sufficient.** Every standing rule an agent needs is written here, stated generically and safe to publish. Nothing refers to private material, and nothing here is read from outside except the family's public repositories.
- **Reading goes one way.** Private work may read Althing; Althing never reads back. Althing also never writes to a tool from its own code: no push, tag, publish or pull request (the rail `code/read-only-to-tools`).

## Regions

Eight regions, each with one job and a checked shape.

| Region | Its job | Its shape is held by |
|---|---|---|
| the root | the front page, the thesis, the operating docs, the license, the package manifest | `layout/root` |
| `family/` | the canon, the registry of repositories, the map, the contracts index, the inventory, parked ideas, the history | `layout/family`, `canon/registry-consistent` |
| `method/` | how the family is developed, the rulings ledger, this record | `naming/kebab`, `rulings/ledger` |
| `releases/<version>/` | one release: its manifest, plans, brief templates and its one loop | `layout/release`, `release/manifest`, `loop/shape`, `freeze/holds` |
| `research/` | dated investigations | `layout/research`, `freeze/holds` |
| `workspace/` | `ws` and the checks that need several repositories at once | `code/read-only-to-tools` |
| `rails/` | the detectors behind the gate, with their tests | the content rails |
| `.claude/skills/` | one procedure per moment | `skills/frontmatter` |

Four content rails hold every region that has text: `lang/english`, `boundary/no-private-paths`, `boundary/no-binaries` and `secret-scan`. The gate's own files (`.yggdrasil/`, `.githooks/`, `.github/`, `.claude/settings.json`) carry the rails that fit them.

**Every region is a node of the Yggdrasil graph, and every file belongs to one node.** A file outside every region is unmapped, which turns the gate red, so placement is enforced for free. A new region is a change of architecture, which is the owner's; a new release directory gets its nodes from `ws release open`. A region's node is created with its first file, because a node may not map a path that does not exist.

**Nodes are siblings, not a tree.** A child node inherits its parent's rules, and the loop, the fixtures and the detectors' data must not inherit the rails of the region around them. Links between regions go through declared relations, which must form a graph without cycles, so they run one way: the root documents link down into the method, the rails, the workspace and the skills; the skills link into the method; the method links into the rails and the workspace and names a root document in backticks instead of linking it.

## Three deliberate choices

- **No hand-maintained inventory.** A list that grows by hand rots first. The front page names the regions, which are fixed; `releases/INDEX.md` and `research/INDEX.md`, which grow, are generated by `ws index` and checked to be in sync.
- **The rails are code with tests.** Each detector is a plain module in `rails/` with its tests. The Yggdrasil adapters, the git hooks and CI all import it, so one detector serves the tree, the staged diff, the pushed range and the commit message, and a rule is written once. Yggdrasil folds an imported module into the rule's hash, so editing a detector re-opens its verdicts.
- **The operating doc is `AGENTS.md`.** Agents of every kind read the same rules; `CLAUDE.md` imports it and adds only what is specific to Claude Code. The Yggdrasil block sits at its end between markers, so `yg init --upgrade` rewrites only that block and the operating doc survives every upgrade.

## The gate

### Blocking is rationed

A rail blocks only what cannot be undone or is broken by construction. In a public repository that is a private name, non-English text, a secret, a machine path, a binary file, a session link in a commit message, a broken link and a broken loop record. What only helps a reader find things stays advisory. Friction trains the habit of skipping the hooks, and a skipped hook skips the rails that matter too. No new rule is enforced until the same violation has bitten three times.

### A verdict is a function of the repository

Yggdrasil caches a script verdict by what the check reads. A check that read a key, an environment variable or a file outside the repository would cache a verdict that a change of that input could never re-open. So every rail whose input is the tree is a Yggdrasil rule, and the rails that need a secret or git history (the keyed names scan, commit messages, the pushed range) run from the git hooks and CI through `rails/run.mjs`. The rule `hooks/wired` proves they stay wired in.

### Consent by reach, applied to Althing

A rule that reaches a whole type of file is the owner's to admit (`type_law.ratification: true` in the graph's config); until he ratifies it, it stands advisory. He ratified the starting set in one batch on 2026-10-06. This is the family's own consent rule (`consent-by-reach`) applied to the repository that develops the family.

### English only

Everything committed is English, because the reader the repository is public for shares English with the family's code ([language](language.md)). The detector looks for Polish letters, Polish function words and Polish-looking words, in prose and in the places where one word is already a signal (headings, file names, slugs, tags, branch names). It was calibrated against a real Polish release loop and against every family repository's English documents before it was enforced: a rail that raises false alarms on its first day gets weakened in its first week.

### No binary files

A text scan cannot read a screenshot, and a screenshot of a private system is the easiest leak there is. So no image, recording, archive, font, office document or PDF enters, and no file with a NUL byte near its start. A diagram is SVG or text; a public picture is linked where it is already public.

### Paths, and the one allowance

No absolute path under a home directory, the system temporary directory or a Windows user folder, no `file:` URL, and no relative link that climbs out of the repository. Every repository path in the record is relative. The one exception is the worktree a lease ran in: Jarl writes it into the loop's record, it reveals only a user name, and rewriting the log would move the done gate. So inside a release loop, and only in that field and that log segment, the two worktree shapes are allowed. The allowance is the honest minimum until Jarl can resolve paths per machine.

### The keyed names rail

The private names a public repository must never carry are on a deny-list that lives only on the owner's machine. A plain salted hash of that list would not protect it: a list of company names has little entropy, and anyone can hash every registered company with the committed salt and find the matches. So what is committed is an HMAC of each entry under a secret key, padded with random decoys so that the file reveals neither the names nor how many there are. The key lives on the owner's machine, in his backup and in one CI secret on Althing alone. A finding names the file, the line and the size of the window, never the entry. Names are matched on whole words, so a client's name does not flag an unrelated common word that happens to contain it. How entries and text are folded, and the rail's states, are in [the rails' README](../rails/README.md).

On a pull request the scanner runs from the base commit, so a pull request cannot change the scanner to send the key anywhere. A new key means regenerating the digests from the plain list in one commit.

### The pre-push hook is the leak gate

Once a commit is on a public remote, forks, caches and GitHub's events keep it; deleting it later does not unpublish it. CI runs after the push, which is too late to stop a leak, so the pre-push hook is the gate: it runs the names, message, English, path, binary and secret detectors over every commit in the pushed range, its patch and its message included, so something added and then removed is still caught. A push to the canonical repository that the names rail cannot scan is refused; a push to any other remote goes through with a line saying it is unscanned. CI on push is detection and alarm, and a nightly scan of the whole history backs it up.

The first push carries one commit. The local history of building Althing holds every intermediate state of the move, and the honest way to be sure none of it travels is not to publish it. After the first push, commits are ordinary and history is kept; a loop's own history is its log, not git.

### CI in two jobs

The Yggdrasil fill executes the tree's own rule code, which on a fork's pull request is untrusted. So the job that runs it holds no secret, and the job that holds the names key never runs on a fork's pull request.

### Commit messages

A message is English, links nothing but public GitHub and the family's own sites, names no local path, and carries no Claude-Session trailer and no session or private link; standard trailers are allowed. A link to an agent session in a public history points at private context.

## Releases and the workspace

- **One directory per release**, `releases/<version>/`, holding the manifest, plans, brief templates and the one loop, and nothing else; a directory with only a manifest is a release whose record is not public, or a patch that needed no loop ([releases](releases.md)).
- **The manifest** (`family-release/1`) names each repository's version, branch, exact commit and check, and the driver Jarl that writes the loop, pinned to a commit. Release loops run on names and relative paths only.
- **Briefs are templates** rendered per machine, so a committed brief carries no machine path and no session trailer ([loops](loops.md)).
- **The workspace** keeps development and verification apart: development happens in sibling checkouts and worker worktrees, verification in Althing's own clones and per-commit trees, never in a checkout that workers are patching ([the workspace](../workspace/README.md), [environment](environment.md)).
- **Where a test belongs.** A test belongs to the repository whose commit must change when the test's expectation changes. When an expectation can only change through commits in two or more repositories, the test belongs to Althing.
- **Where work happens.** Prose work in Althing happens on `main` in the one checkout; code work in `workspace/` and `rails/` gets a worktree, because several code issues can run at once.

## What was left out, and why

- **No rule that a loop declares its check.** Jarl's own status already says when a loop lands on testimony alone.
- **No rule that quotes are marked.** The marker is a rule of the operating doc; a pattern over prose would flag every quoted sentence that is not the owner's.
- **No rule over the graph itself.** The graph's rules are thin adapters over tested detectors. A rule over `.yggdrasil/` is added the day the graph grows real rule logic.
- **No issue tracker on GitHub.** The loops are the backlog; a report goes to the tool's own issues and is triaged here ([issues](issues.md)).

## The honesty line

A green gate proves that the rails passed: the files are English, carry none of the deny-list's names, keep their structure, and leak no machine paths, binary files or secret shapes. It does not prove that nothing private leaked: a paraphrase can identify a client without naming one, and no detector proves an absence. It does not prove that a translation is faithful. It says nothing about whether a release is good. A green check is never presented as "safe to publish" or "the release works".
