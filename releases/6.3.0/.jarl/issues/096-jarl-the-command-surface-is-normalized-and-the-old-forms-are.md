## What
Ruling normalize-the-surface-old-forms-out. At release/6.2.1 7a10c53 Jarl has 44 commands and about 17 read views; an issue's field is changed by field and also by prio, tag, files, repo, source and after, each with its own grammar; --by is the author on writes and the grouping in status and models; free text is a field named why, text, findings, what, question, answer, ruling, event or reason depending on the command; the author is required on review, defaults to the owner on answer and decide, and is optional elsewhere.

## Why
An agent pays for every form it must remember and every wrong guess; one form per thing, refused old forms that name the new one, and fewer views are what lets the guidance shrink (088).

## Acceptance
- One command changes any field of an issue (header fields and the description's sections) with one grammar for setting, adding, removing and clearing; prio, tag, files, repo, source, after and body are removed, and each removed command is refused with one line naming the form that replaces it
- A flag name means one thing across commands: --by is always the author; grouping is --group in status and models; --kind is the kind of the thing the command writes or filters; a test over the command table checks it
- Free text has one name in every tool (text) and one place in every command's usage
- The author is required on every write that records a judgement (review, answer, decide, retract) and optional elsewhere; an unnamed write shows as unnamed (as 085 says)
- The read views are reviewed against next --as (052): a view that only shows part of another is removed or folded into it, refused with the view that replaces it, and the help gives each remaining view one purpose in one line
- Every refusal ends with a ready command or the flag to add (folds 053); SKILL.md and the references use only the new forms
- Easy for an agent (ruling surface-easy-for-agents): a fresh agent on the light tier, given only SKILL.md and the help, files an issue, changes its fields, leases it, records proof, records a review, answers a question and closes it on a scratch loop, with no call refused for a wrongly guessed form; its transcript is kept in research/2026-11-03-jarl-as-a-loop-tool

## Changelog
- Changed: Every change to a task's description now goes through one command, field: give a part a value to replace it, or add to it, take items off it or clear it with --add, --remove or --clear. The commands that each changed one part (body, tag, prio, files, repo, source and after) are gone: using one prints the form of the field call that does the same, for you to fill in. A repository's base branch is changed with base, and set takes statuses only.
- Changed: The counts of status and models are grouped with --group, and --by always names who did a write. check is no longer a second name for scope, and a review or a piece of proof is taken back only with retract; each old spelling is refused with the form of the call to use instead.
- Changed: Free text is given the same way to every command: as the last argument on the command line, and as the field text in the tools. A tool given a field by a name it no longer has, such as why or findings, or by on status, says which field to use.
- Changed: An answer and a ruling given on the command line or through the tools now always say who gave them: answer and decide need --by, and nothing is taken to be the owner's or the coordinator's when no name is given. A tool built on the record library records an answer as the owner's and a ruling as the coordinator's when it names nobody, as before.
- Changed: When Jarl refuses a call, it says what is wrong, naming the word of your call that is, and the last line of the message is the form of the command that does what you meant, with a <placeholder> for each value only you know and the values allowed named in the message: fill the values and run it. Jarl never writes a value in for you, never corrects your call into one that runs, and never puts in a command what only someone else may do, such as the owner's answer or an approve; a step that has to come first, such as a question to the owner, is a command on its own line. A call that still holds one of Jarl's placeholders, wherever it stands (--root included), is refused, so a form pasted as printed writes nothing; any other text in angle brackets, such as <nil>, is a value like any other. The form keeps the --root and --json you gave as you gave them, also when you wrote them after a bare --, and it holds everything else the command needs, such as --by for who you are, so once filled in it is not refused for a part it left out. Every command Jarl prints, in a refusal, a note or a view, carries the --root you gave, and is written for a POSIX shell (sh, bash, zsh) on macOS and Linux and for PowerShell and cmd on Windows, every word quoted for that shell and every placeholder in double quotes, on one line; Git Bash on Windows reads those commands too, but for a path that starts with two backslashes. Replace every <placeholder> before running one.
- Changed: The merge queue and the branch tips are read in resume: tips and queue are gone, and using either prints the resume call that shows the same. resume --repo narrows both to one repository, --base sets the merge queue's base, and --gh asks gh for the CI of the tips (resume --ci is refused with the form of the --gh call; a tool built on the record library still asks with ci).
