It starts no worker, no reviewer and no merge, and it writes nothing to the loop, until the owner tells it to continue. The machine that wrote this note has stopped and runs nothing; two machines never run the loop at once.

2. `yg check`, then `node workspace/ws.mjs doctor` (`doctor --fix` sets the hooks). The names key comes from the owner; without it the machine is a contributor's machine and cannot push to the canonical Althing.

## How the loop is run (when the owner says to continue)

- The briefs are templates in `releases/6.3.0/briefs/` (worker, reviewer, merger), rendered for the machine with `node workspace/ws.mjs brief <role> --release 6.3.0 --repo jarl --issue N`. They carry the standing rules; read them once, they are current.
- A package is a few neighbouring issues for one worker on one branch cut from the release branch, in its own working copy `~/Worktrees/JarlSkill/<name>`, leased with `ws jarl set <ids> in-progress "<why>" --branch … --worker … --worktree …`. Models come from the `model-choice` skill: Haiku at max for small test-decided issues, Sonnet at high for ordinary ones, Opus at high for format, gate and core work, Opus at xhigh for a takeover and for reviews of Opus work. A reviewer is never weaker than the worker and never Fable (ruling `no-fable-model`).
- Review is a fresh agent with the bounded brief. After three rounds of "changes" a fresh strong worker takes over with a changed approach. A review that finds something outside the issue files it as an issue, or, if it is only wording, taste or an input no one is expected to give, it goes on the known-limitations list.
- Merge with `git merge --no-ff` in the release worktree, run the full suite there with `TMPDIR` from `mktemp -d` under the system temporary directory, then `ws jarl evidence … --ran … --saw …`, `ws jarl merged <ids> --sha <sha> --ci none --repo ../../../JarlSkill`, `ws jarl set <ids> done "…"`, remove the worker worktree and branch by name, commit the loop state in Althing and push it (`ask-012` grants the push when the rails are green).
- Lessons worth keeping: a worker's last message sometimes says it is waiting on its own background work and is then followed by the real report, so wait for the second one; clean the system temporary directory only by the names of your own folders, never by a pattern; the log is never edited by hand (one line was reworded once on 2026-11-05, with a disclosure in its commit, because a reviewer's example path tripped the private-paths rail); nothing has run on Windows yet, and the first real Windows result is CI on GitHub after the owner pushes.
