## 2. Owner decisions

**D1 · 1.0.1 or 1.1.0.** (a) 1.0.1 with P1-P5 only: edge changes through internal code, no new export, option or field, exactly what `docs/api.md` allows a patch. (b) 1.1.0 adding optional inputs: a diagnostics callback (074), a C# reachability predicate (014, 075b), an injected file view of the commit tree (Grain 099/106, 010). Recommendation: (a) now; (b) as its own designed minor after 6.1.1. If (b) is chosen, the branch name `release/1.0.1` no longer fits.

**D2 · 012: a repository that declares no workspace.** (a) Keep today's index of every package.json when the importer has no workspace root above it (no root `workspaces`, no `pnpm-workspace.yaml`), and use members only where a declaration exists. (b) Strict: only declared members and `workspace:`/`file:`/`link:`/`portal:` dependencies, everywhere. (c) Also follow `node_modules` symlinks. Recommendation: (a): it fixes jest and react, keeps recall for undeclared layouts and keeps the three existing workspace catalogue cases green; (c) is rejected because an install is untracked local state (the 010 principle).

**D3 · 010: recall in a clean checkout.** (a) Map an `exports`/`main`/`types` target under the package's `outDir` back to its source through that package's tsconfig (`outDir` → `rootDir`), as TypeScript's project-reference redirect does. (b) When no target exists, attribute the import to the owner of the package's `package.json`. (c) Leave it silent and let Yggdrasil warn that a package entry points at missing files. Recommendation: ship only the determinism half in 1.0.1; (a) as a separate Runes issue (M), after Yggdrasil's git-ignore half lands, because it is a new resolution rule with its own false-edge risk; (b) is coarse and wrong when nodes map `packages/*/src/`.

**D4 · 009: how far the namespace-root rule reaches.** (a) The issue's rule only: an ancestor strictly below a discovered project root is never a root (the importer's own directory excepted). (b) In addition, a standard-library top-level name never matches an ancestor root other than the importer's own directory and the repository root (`python -m` from the root), which also covers repositories with no Python manifest. (c) Keep an ancestor holding `conftest.py` as a root (pytest prepend mode). Recommendation: (a)+(b); not (c) in a patch, since a prepended directory shadows the standard library and reopens the trap.

**D5 · 011A: several referenced configs include the file with different `paths`.** (a) Silence (`'unknown'`). (b) The first reference in declaration order wins (closer to tsserver). Recommendation: (a), the zero-false-positive rule the resolver follows elsewhere.

**D6 · 018 part 2.** (a) Member-level recovery in 1.0.1. (b) Part 1 now, part 2 as its own issue if the probe shows no cheap rewrite. Recommendation: let the worker probe; accept (b) if part 2 exceeds M.

**D7 · 014 and 075 part b: C# reference closure.** Restrict C# symbol candidates to the projects the caller's project can reach (`ProjectReference`, `<Reference HintPath>` to in-repo assemblies, `Directory.Build.props` imports). Options: (a) in Runes: `csharp-project.mts` reads the reference graph and `makeResolver` gets an optional reachability predicate (a minor); (b) in Yggdrasil's pass, filtering after resolution (Grain would not get it); (c) defer. Recommendation: (a) in 1.1.0 with its own design issue; ship 075 part a now.

**D8 · Grain 053: Java same-package references.** Grain binds them (`relations.mjs:84-149`), Runes does not. (a) Move the binding into Runes (Yggdrasil's check becomes stricter on Maven/Gradle graphs: test → main relations become required). (b) Grain stops declaring relations Yggdrasil cannot verify, in Grain 6.1.1. Recommendation: (b) for the patch; (a) only in a minor with a Yggdrasil CHANGELOG warning.

**D9 · 074: report a tsconfig/package.json that cannot be parsed.** Needs a diagnostics channel out of `makeResolvePathToFile` (a new option). Recommendation: strip the BOM in 1.0.1, defer reporting to the 1.1.0 design (D1 b).
