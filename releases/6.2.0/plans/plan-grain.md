## 0. Conventions every package follows (the file-disjointness below depends on them)

- **Version stamps are not bumped by workers.** `engine/config.mjs` holds `EXTR_V` (g36), `HIST_V` (h15) and `MODEL_V` (m39) on single, very long lines; every package that bumped one would conflict with every other. A worker writes `Needs: MODEL_V` (or `HIST_V`, `EXTR_V`) in its commit message body with one sentence of rationale; the final pass (director) bumps each needed stamp once, with a consolidated rationale. Tests build fresh fixtures, so they never depend on the bump.
- **Shared prose is written once, at the end.** `CHANGELOG.md`, `docs/reference.md`, `docs/validation.md`, `docs/results.md` and `README.md` are not edited by packages (except 131, which owns README and runs last). A worker puts the exact doc delta it needs (section, sentence) in the commit message body under `Docs:`; the final pass applies them. Issues whose acceptance asks for a doc line: 054, 107, 111 (optional), 119, 123, 124, 129, 133.
- **One new test file per issue**, named for what it proves (`tests/<topic>.test.mjs`, kebab-case like the existing ones), unless the acceptance names an existing test file; those named files are listed in the package's file set.
- **One commit per issue**, message naming the issue (`… (issue NNN)`), identity `Krzysztof Dudek <me@chrisdudek.com>` (already Grain's local `user.email`).
- **`engine/vendor/runes/**` is never edited** (the offline gate in `npm test` compares it byte for byte with the pin). Runes-side work goes to the Runes loop (`release/1.0.1`) and reaches Grain only by `npm run runes:update -- --tag v1.0.1` after Krzysztof pushes that tag.

## 2. Owner decisions

**D1 · Absence rules (039, 040).** Grain certifies "this partition never does X" (since 6.1.0 that means "less often than elsewhere"), and today such a row becomes an `enforced` prohibition when its drill passes; the proposal's own preamble and README say Grain never decides what a codebase must never do. Question: may an absence ever be enforced or certified? (a) Never enforced: an absence row is a draft with `absence-not-forbiddance` like the sub-gate ones; costs some true prohibitions (an absence that really is a boundary is still expressible as a maintainer `decide boundary`). (b) At most advisory: yg reports it, never blocks; the false alarms (javapoet's `@Override`, click's `@click.argument`) still reach every check. (c) Enforced only when the partition has zero deviants and no certified cell doing X; keeps a rare true prohibition at the price of a new threshold. For 040 additionally: in the patch, suppress a partition-wide absence contradicted by a certified presence cell in the same partition; redesign the contrast in 6.2. Recommendation: (a), plus 040's contradiction filter in 6.1.1.

**Hooks when HEAD has moved (107).** Hooks answer from the index built for an older HEAD and say false things with confidence (placement into a directory that was just renamed, a FIRST edge that exists 29 times). (a) Silence while `meta.headSha ≠ HEAD`: never a false note; costs every unbidden note after each commit until the agent's next real query (hooks never build, and the MCP server does not warm the index). (b) Speak, marked `(STALE)`: keeps the signal, but a STALE note can still be a false placement or edge note. (c) Refresh incrementally inside the hook: correct notes, but breaks "hooks never build", costs seconds per edit after a commit, and without a lock (133) parallel hooks rebuild in parallel. Recommendation: (a) for 6.1.1, with SessionStart saying notes are paused until the next query; (c) with a lock is a 6.2 design.

**D3 · Java same-package references (053).** Grain binds a same-package simple name (`new Owner()` without an import) as a dependency; Runes, and so Yggdrasil, does not; on Maven/Gradle repositories `yg advise` calls Grain's test→main relations stale right after adoption. (a) Move the binding into Runes and bump it in Yggdrasil: the truer model, but `yg check` turns red on existing Java graphs (a minor-release change, needs a Runes release). (b) Grain stops declaring what Yggdrasil cannot verify, in 6.1.1: the two tools agree today, true test→main dependencies go unstated until (a). (c) Keep and document the divergence: the tools keep contradicting each other. Recommendation: (b) now, (a) in a minor with a Yggdrasil CHANGELOG warning (the Runes planner recommends the same, its D8).

**D4 · `--shape types` (045, 130).** In the opt-in types shape, rules attach to a host type that gets no node, so after adoption they are effective on zero nodes while the proposal calls them enforced; and the type relations it writes lack `default: deny`, so they block nothing while the type description says `yg check` refuses. (a) Make it enforce: give rule-host types a node and write `default: deny`; changes what the shape enforces, needs real adopt-and-check tests. (b) Make it honest: in types shape such rules stay draft with a reason, the report counts the relations and says they do not block, the type sentence stops promising refusals; nothing new is enforced. (c) Mark `--shape types` experimental in 6.1.1 and fix it in 6.2. Recommendation: (b) for the patch.

**D5 · A one-time history re-parse in 6.1.1 (041, 043; also any Runes re-vendor).** 041 (CommonJS `require` invisible to the convention layer) and 043 (indent unit misread on deeply nested files, spoken unbidden by the post-edit hook) change extraction output, which lives in the history blob cache; fixing them needs an `EXTR_V` bump, and the first query after upgrading re-parses the whole history once, like a first index (Yggdrasil itself: 157-322 s cold). The 6.1.1 engine bump already forces a full history walk and a HEAD re-parse, but on the warm blob cache. (a) Take them: one `EXTR_V` bump, CHANGELOG Upgrading step 2 rewritten. (b) Defer 041 and 043 to 6.2; the CHANGELOG line stays true. A related fact: if Yggdrasil 6.1.1 moves to Runes 1.0.1, Grain must re-vendor it too (Grain's seam test requires the same Runes as Yggdrasil), and the Runes stamp clears the blob cache by itself, so (a) then costs nothing extra. Recommendation: (a).

Defaults taken without asking (owner may overrule): 133 records "no lock between parallel builds" in docs instead of adding one; 044 renames the clause rather than deleting it for untracked families; 059 treats a duplicate decision as a refusal (exit 1); 128 refuses rather than judging content under `--as`; 062 uses a bounded explicit rename limit plus disclosure rather than an unbounded one.

## 5. Repo mechanics

- **Branches and worktrees.** Cut each worker branch from `release/6.1.1` after the packages it waits for are merged; merge back `--no-ff` with a message naming the issues; never push. The 6.1.0 loop kept worktrees at `~/.jarl-wt/<Repo>-<NNN>` (the Runes workers of this loop are there now: `~/.jarl-wt/Runes-009` …), so: `git -C ../../../Grain worktree add ~/.jarl-wt/Grain-036 -b jarl/036-range-not-an-option release/6.1.1`. No `npm ci` is needed in a worktree (runtime, grammars and Runes are vendored; `npm ci` only for grammar builds, not in this patch). The main checkout is clean.
- **The check.** From `plugins/grain/`: `npm test` = the offline Runes gate, then `node --import ./tests/git-env.mjs --test tests/*.test.mjs tests/relations/*.test.mjs tests/relations/e2e/*.test.mjs tests/relations/e2e-cli/*.test.mjs`. On this branch: 1853 tests, 1827 pass, 26 skipped (no `YG_BIN`, or Windows-only), about 90 s wall at ~7 cores. The full gate: `YG_BIN=<the session scratchpad, since lost>/grain-611/ci/yggdrasil/source/cli/dist/bin.js HORDE_DIR=<the session scratchpad, since lost>/grain-611/ci/horde GRAIN_CORPUS_CLONES=<the session scratchpad, since lost>/grain-611/corpus npm test` → 1852 pass, 1 skip, about 160 s (seams alone about 115 s). That Yggdrasil copy is a frozen 6.1.0 build (2493aa16) with its git checkout three levels up, which `tests/seams.test.mjs` needs; do not point `YG_BIN` at `../../../Yggdrasil`, which its own workers are patching. `yg` 6.1.0 from npm is also on PATH. Iterate on one file with `node --import ./tests/git-env.mjs --test tests/<file>.test.mjs`; run the full gate before reporting; stagger full runs, several in parallel saturate the CPU. Packages whose acceptance needs Yggdrasil (035/060 and 045: a real `yg adopt`; 046, 039 and 040: `enforced` exists only after a real drill; 053: `yg advise`) must run with `YG_BIN`, otherwise those tests skip and prove nothing.
- **Fixtures and repros.** The deterministic fixture is `tests/fixtures/build-fixture.mjs` at the repository root (HEAD 47da000); `tests/stress/` (root and plugin) is not part of `npm test`. Each issue names its verifier's repro scripts under the bug-hunt scratchpad (`…/scratchpad/bughunt/grain/verify-NN/`); reuse them for red→green evidence. Corpus clones for evidence runs: `…/scratchpad/grain-611/repos/` (express, flask, gin, koa, petclinic, spring-petclinic) and `…/grain-611/corpus/` (express, spring-petclinic). Never run `grain` with the repository that holds the loop as repository or cwd; always `--repo` on a fixture or clone, from a scratch cwd.
- **Cache stamps.** `ENGINE_VERSION` is already 6.1.1, so the first 6.1.1 query in any repository discards the HEAD tree cache and walks the whole history again on the warm blob cache (`ensureFresh` passes `full: … || !versionOk`, grain-context.mjs :264). A `HIST_V` bump therefore costs adopters nothing extra in this release; an `EXTR_V` bump or a Runes re-vendor clears the blob cache (keyed on `extractionStamp`) and re-parses all history (D5). `MODEL_V` costs a re-learn only. Workers state needs, the final pass bumps (section 0).
- **Traps.** `docs-audit.test.mjs` requires exactly one `switch` in `engine/grain.mjs` and a doc for every dispatched command; `docs/validation.md` must keep "(N tests under engine 6.1.1"; the CHANGELOG has an empty `[Unreleased]` above `[6.1.1] - 2026-10-02`, and 6.1.1 fixes go under [6.1.1], in the adopter register (no file names, Ratatoskr plain language, stop-slop); CI runs Node 22 and 24 on Ubuntu and Windows, so symlink and case tests need a Windows/case-sensitivity skip with a reason; git ≥ 2.24 for `--end-of-options` (local 2.50.1, node 24.11.1).
