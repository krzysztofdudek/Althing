## What
After 119 a file over 1.5 million characters is named, but its types still do not give the edges yg check sees. Extracting only the relations costs about 6 s per refresh at 1.54 million characters (28 s at 6.18 million), so the result needs to be cached.

## Why
Generated API clients are a common case; Grain and yg diverge in edge counts.

## Acceptance
Relations from over-limit files are computed once per file version and cached; edge counts match yg check.

## Changelog
- Fixed: a source file over 1.5 million characters (a generated API client, say) still adds no conventions, but its dependencies are now counted, so Grain's edges match what yg check sees. Grain reads such a file once per file version, in a folder without git too, and gives the read at most 90 seconds per file. When a read gives no dependencies, status and report name the file and say why. A read that did not finish (the 90-second limit, a stop from outside, memory the machine did not have) is read again by grain refresh; when the parser gave up on the file itself the answer is kept, and grain refresh --full reads the file again. grain measure names such a file and counts its dependencies once it has been read. Can turn a repository red: edges that were missing appear, and a graph that did not declare them fails yg check.
