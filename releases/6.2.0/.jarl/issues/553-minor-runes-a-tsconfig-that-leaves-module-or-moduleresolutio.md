## What
Minor: Runes: a tsconfig that leaves module or moduleResolution unset (or sets module commonjs alone) keeps the first-target reading of exports, where TypeScript 6.0.3 resolves it as bundler: with an exports entry listing import before require, a .cts or .cjs file, an import x = require() and a require() call bind the import target and the compiler the require target (63 of 180 compared rows for {} and for module esnext alone, 141 of 180 for module commonjs alone). It existed before 491 and 526, which do not name it.

## Why


## Acceptance


[test] A tsconfig that leaves module or moduleResolution unset resolves exports as TypeScript 6.0.3 does for that tsconfig, checked by the compiler comparison test with rows for {}, module esnext alone and module commonjs alone · by: npm run check

## Changelog
- Fixed: a `tsconfig.json` that leaves `module` or `moduleResolution` unset is read with TypeScript 6's defaults (`module` from `target`, Bundler unless `module` says otherwise), so a `require()` call, an `import x = require()` and a `.cts` or `.cjs` file bind the `require` branch of a package's `exports`, and an import whose branch names no file binds nothing. A consumer's graph can lose a relation that named the wrong branch and gain one for the right branch.
