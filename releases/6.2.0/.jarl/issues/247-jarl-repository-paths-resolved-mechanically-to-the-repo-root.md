## What
Back from deferred (ruling jarl-6-2-0-scope-revised): 246 and 247 trade contents (the design research/2026-10-08-jarl-field-report-and-repository-names/design.md, A.2 and A.4), and 247 becomes the repositories entity, which its title already names; "finding moved ones" is now the root-commit check, which finds a wrong or moved checkout and names the fix. Today Repo holds a path relative to the loop's root (repoOf, jarl-lib.mjs:2203-2208 at 2c12aa3). A path says where, not which: any repository at ../../../Grain is read as Grain, and nothing checks that it is one. It encodes the loop's depth and the sibling layout (the loop survived its move only because the new directory sits at the same depth, ruling althing-move). A worktree path passes as a repository of its own. The Worktree field and the lease lines record an absolute path that belongs to one machine (:1213). And the base is whatever the checkout has checked out (defaultBase, :2231), read by check, queue, tips and branches. The principle: the record holds identity, the machine holds location, and Jarl checks one against the other where it acts, and never guesses. A sibling repository is named by the directory git clone gives it, which is its name on its host and already every Files prefix (the registry's keys are not used: Jarl cannot read Althing's registry). Jarl declares it once, by itself, in .jarl/repos.md, with its root commits (all of them), its origin as found and its base branch, and no path; a name resolves to the sibling of the loop's main checkout; a repository that is not a sibling keeps a path, as today; a machine laid out differently puts a symlink beside the loop's checkout, and Jarl needs no code for it. The record holds no worktree location: a lease is its Branch, Worker and Since, and git allows a branch in at most one worktree, so views ask git. Dropped by the ruling, not carried to 6.3.0: discovering moved repositories among siblings, and checking that declared files exist on the loop's branch. Left out: a per-machine override file and a migration command (paths read for ever; a loop gets names from its next issue on, and an open issue is re-pointed with repo <id> <name>).

## Why
A fragile detail repeated in hundreds of issues: a wrong checkout is read as the right repository with nothing to catch it, a moved loop breaks every path, and a record that is public carries one machine's home directory and user name. With names and identity, every role finds the real checkout and worktree through the calls it already makes, on the machine where it runs, and the record holds nothing that belongs to a machine.

## Acceptance
- A repository an issue names is declared by Jarl, once, in .jarl/repos.md (name, roots, origin, base) with a log line, holding no path; repo --base <name> <branch> changes a base with a log line; repo logs every change. An issue with no Repo is read exactly as today, in the loop's root
- A name resolves to <parent of the loop's main checkout>/<name>, the main checkout found through git's common directory by the helper 306 introduces (reused here and by 251, never written twice), so a loop opened in a linked worktree finds its siblings beside the main checkout. The root commit is checked by the commands that act (check, merged, repo, new --repo, import --repo) and by verify, never in the read-only views, with an unverified state for a shallow checkout and a note, never a refusal, for a different origin. A name that does not resolve, or resolves to another repository, is shown with its fix (put the checkout, or a symlink to it, at <parent>/<name>), refused by the commands that act, and marked by the views
- --repo takes a name, a checkout, a worktree or a file inside a repository, reduced to its main checkout through git's common directory. It stores the name where the checkout sits at the convention's place, and the path otherwise, with a stderr note saying why (so two repositories sharing a directory name stay apart). The loop's format decides how a value is read: in the old format every value is a path; in the new one a value starting with . or / (or a drive letter) is a path and anything else a name. The first write of a name raises the format first (252), under the same lock, rewriting any bare-word path as ./<word>, and the pinned Jarl 6.1.0 fixture of 252 refuses list and status on that loop, tested. Merged's in part follows Repo; the Files prefix rule and the rule for a repository holding a directory of its own name (:1485-1488) stay as they are
- No worktree location is recorded from now on: a new lease stores no Worktree field and its lease line no worktree path. Views read the worktree of a lease's branch through 241's lookup (here; listed but not visible from here; elsewhere, locked with a reason; no worktree holds the branch), in each repository the issue names. In the CLI and the MCP tool, set --worktree checks the path (when it exists, it must be a worktree of one of the issue's repositories with the lease's branch checked out, or the call is refused) and stores nothing. The record library (record.mjs setStatus) stays tolerant: a worktree opts key a composer passes (Horde does) is accepted and not stored, with no refusal and no change to the jarl-record/1 contract. A lease from before keeps its Worktree field and is read as today until it ends; the done gate is untouched
- show, show --json (as where) and status --by repo print where each repository and the lease's worktree are on this machine, on stdout only; status --by repo also prints each repository's base and whether its checkout is on it (a warning only in 6.2.0); nothing resolved is written
- Tests: a loop over two sibling repositories gets names, and keeps a path for a third that is not a sibling; a symlink beside the loop's checkout resolves a name; a checkout of another repository under the right name is refused by its roots; a fork with another origin passes with a note, and a shallow clone reads unverified; a loop opened in a linked worktree resolves its siblings beside the main checkout; a lease's worktree is found by its branch, including one git lists as prunable; set --worktree through the CLI refuses a wrong path while record.setStatus with a worktree key does not; the real loop through JARL_LIVE_LOOP when it is set (269)
- Not here: a per-machine override file (kept out by jarl-6-2-0-scope-revised), a migration command, discovery of moved repositories and per-file existence checks (dropped)
