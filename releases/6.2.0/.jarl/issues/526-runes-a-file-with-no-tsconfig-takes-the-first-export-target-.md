## What
482 selects export conditions by the importing file's module settings, and keeps the old reading where no tsconfig decides. In react most files have no tsconfig, so the first target that exists on disk wins, which is often a react-server, edge or native build no resolver would pick by default.

## Why
1115 edges in one widely used repository point at files the real tools do not read.

## Acceptance
- A file no tsconfig covers resolves exports with the default conditions Node and TypeScript use (import or require by format, then types, node, default), with cases for react-server, edge and native targets, red before and green after
- react's heavy-tier oracle mismatches of this kind are gone, and its golden changes only by lines this explains

## Changelog
- TS/JS: an import in a file no tsconfig covers binds the target that Node and TypeScript choose from a package's `exports` (`import` or `require` by the file's format, `types`, `node`, `default`), so a `react-server`, `workerd`, `edge-light` or `react-native` build is no longer taken for `default`; a `require('x')` call and `import x = require('x')` read the `require` condition, and a dynamic `import('x')` the `import` condition except where the compiler emits it as a `require` (outside the Node module settings and `preserve`, in a file emitted as CommonJS, such as a `.cts` file or any file under `module` commonjs), where it reads `require`; an import type (`typeof import('x')`, `import('x').T`, `x is import('x').T`, a type argument, `keyof import('x').T`, a template literal type) reads the condition of its file's format, and an `import('x')` in the `extends` clause of an interface or the `implements` clause of a class is a dynamic import call, as the compiler resolves it; a `types@<range>` key is entered when TypeScript 6.0.3 satisfies its range and passed over when it does not. `export interface I extends import('x').T {}` gives no edge. A consumer's graph can bind these imports to another file of the same package, and an `import('x')` of a package whose `import` target is untracked build output binds nothing.
