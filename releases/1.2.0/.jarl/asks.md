# Questions to the owner

- **a-1** (answered) · charter · Runes 1.2.0 is worked on a branch, release/1.2.0, that exists only on this machine. Runes' CI on GitHub runs the whole suite on Linux, Windows and macOS, and Runes ships only when that CI is green on the exact commit to be tagged (ruling ci-green-on-github-and-bounded-agents of the 6.2.0 loop). For 1.1.0 the owner gave a standing permission to push release/1.1.0 (ruling runes-push-branch), and that permission names that branch only. May the jarl push Runes' release/1.2.0 to GitHub whenever its tip is green here, with no tag and no publish?
- **a-1** option · a, yes, a standing permission for release/1.2.0 (recommended) · CI on all three systems runs after every merge, so a Windows or macOS failure shows at once, next to the change that caused it; the branch is public on GitHub while it grows
- **a-1** option · b, one push at the end, on the owner's word · nothing reaches GitHub until the candidate is ready; Windows and macOS are seen for the first time then, and a red there means a late round of fixes before the tag
- **a-2** (answered) · charter · issue 752 · Issue 752: the Runes package on npm carries the recipe for its 23 language grammars but not the built grammar files, so every program that uses Runes builds 11 of them itself on first use, after downloading a 940 MB compiler toolchain, and cannot do so at all on Windows (Runes/package.json:45-51, Runes/src/grammars/build.mts:128-143). A new family tool hit this. How should the built grammars reach a user of Runes?
- **a-2** option · a, ship all 23 built grammars inside the Runes package (recommended) · the package grows from about 0.5 MB to about 2-3 MB compressed (about 25 MB unpacked); no download and no toolchain for a user, Windows works; every file is still checked against the checksum the package already pins; the release workflow builds them before publishing
- **a-2** option · b, a second npm package holding only the grammars · the main package stays small; a second package to publish and keep in step, and a second trusted publisher to set up on npm
- **a-2** option · c, attach them to each Runes GitHub release and download on first use · no size cost; every fresh machine, container and CI run needs network access to GitHub, and an offline user still builds
- **a-2** option · d, keep today's build and only document it · no work; the 940 MB download and the Windows gap stay
