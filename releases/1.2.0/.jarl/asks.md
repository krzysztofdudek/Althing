- **a-3** (answered) · stuck · issue 741 · 741's line asks that a lone `o is Config`, where Config is a value the file declares, give no edge. C# reads that form the other way: `o is Config` with no designation is the is-type operator, which binds Config as a type first and takes it as a constant only when no type of that name is found (Roslyn's parser turns such a constant pattern into an is-type expression, and its binder tries the type first, for compatibility with C# 6, where a value never hid a type there). So in `class C { const int Config = 1; bool A(object o) => o is Config; }` beside `using Lib;` with a type Lib.Config, C# tests the type Lib.Config: the edge the reader gives today is true, and the line would drop it. The value hides the type only where C# binds the pattern's expression first: a switch arm `Config =>`, `case Config:`, `o is not Config`, an `or` or `and` pattern, a parenthesized one and a positional subpattern (750 already reads that last place so). At 0995b7c all three of `o is Config`, `Config =>` and `o is not Config` read Config as a type. Options: (a) the line as written: every lone constant-pattern name the file declares as a value gives no edge, `o is Config` included; cost: a true edge lost wherever a file has a value and a type of one name, a false green. (b) the C# reading: `Config =>`, `case Config:` and `o is not Config` with Config a value the file declares give no edge, while `o is Config` and each test of a `||` chain keep the edge to the type; the line changes to say so. (c) no change; the false edge of `Config =>` beside a constant of that name stays. Recommended: (b). 741 stays uncommitted until this is answered; 747 goes on.
