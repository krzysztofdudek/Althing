# The Yggdrasil family: the canon

**This is the one place the wording that describes the family is authored.** Every family README's family section and headline, each repository's GitHub description and topics, the GitHub profile (`krzysztofdudek/krzysztofdudek`) and the website (https://chrisdudek.com) quote or adapt this file; none of them originates wording of its own. If a family sentence anywhere cannot be reduced to this canon without losing a real fact, the fact belongs here first: the canon is never allowed to be less true than what it replaces. Drift between this file and the six family READMEs is caught by `node workspace/ws.mjs check canon-sync`, which reads each README from GitHub (or from the workspace's clones) and compares its family section and headline with this file. Which repositories it reads, and which tools the block below must name, come from [the registry](registry.json). The profile, the GitHub descriptions and topics and the website are kept by hand against this file.

Like everything in Althing, this file names no client.

**Self-reference convention.** A README refers to its own repository unlinked: bold name, no Markdown link. In a table row it appends `(this one)` right after the bold name. Every other repository's name in the same section stays a normal link. The block above is written from an outside vantage point: every linked name appears linked. Producing a specific README's copy means, for that repository's own name only: drop the link wherever the bold name appears in prose, and drop the link **and** append ` (this one)` wherever the bold name is the first cell of a table row. Nothing else changes. The "Where it hurts" table names the tools bold and unlinked on purpose, so the substitution never touches it. `ws check canon-sync` applies exactly this substitution before comparing, so the expected six-way difference never reads as drift. A footer that follows the family section (ResearcherSkill's discussions badge, after a `---` rule) is outside the section and is never compared.

**Versioning.** The core (Yggdrasil, Grain and Jarl) ships as one version: Yggdrasil and Grain since 6.0.0, Jarl from 6.1.0, when it jumped from 0.2.0 straight to the family number (ruling `blocks-and-composer`, point 8). Horde shipped on the same number from 6.0.0 until it left the family on 2026-11-04 (below). The number names a set of tools built and tested against each other, not a compatibility promise; compatibility travels in the schema ids and pins registered on [Family Contracts](https://krzysztofdudek.github.io/Yggdrasil/family-contracts). In a release where Jarl does not change, Jarl's changelog says so in one line under the family number. The add-ons (Ratatoskr, Urd, Researcher) keep their own numbers. Runes, the shared code the core tools vendor or install, has its own semver and is not a family member (below).

**Who raises and lowers law.** Read solo, Yggdrasil's own README keeps its truth as written: *"Deciding what is worth enforcing stays with you."* In the family, that sentence does not carry over unchanged. Consent follows reach (ruling `consent-by-reach`): law inside one component is raised freely by the agent working it; a rule or a decision that reaches a whole type is shared vocabulary, so the agent proposes it, it runs as advice at once (a type-reaching rule stands `advisory`, and `yg check` reports `type-law-unratified` for one standing `enforced` without a ratification), and the client admits it in one batch of at most ten when the work closes. A missing ratification never blocks the close; an unratified decision simply stays a ruling of the loop. Only the client lowers or vetoes law. In a graph made mostly of types, that means the agent mostly proposes and the client mostly admits, and the canon says so rather than footnoting it. The family has one human role, not two: a person becomes "the engineer" for exactly the moment they write a rule or lower one themselves; the rest of the time they are the client who ordered a result, was handed the plan in plain words, and can veto it.

**Trust.** Where the repository has a check, the check decides what lands in a Jarl loop (ruling `conditional-trust`). A fresh reviewer can only stop a change, never make a failing check pass, and its approval is recorded as testimony, not as proof. A Jarl loop whose `goal.md` declares no `Check:` line lands on testimony alone, and `jarl status` and `jarl report` say so at the top; `jarl report` also counts how many approvals really came from a fresh reviewer.

**Dependency graph.** Every edge points one way, and Yggdrasil depends on nothing:

| Edge | Kind |
|---|---|
| Grain → Yggdrasil | optional: Grain runs standalone and, when Yggdrasil is present, hands it a proposed graph it accepts with one command. |
| Jarl → Yggdrasil | optional, and only where the repository has a graph and a working `yg`: what the client ratified is written into Yggdrasil's logs (a ruling about a whole type of code into that type's decision log, `yg log add --type`; a rule's ratification into the rule's own log, `yg log add --aspect --ratify`), and the merger passes Yggdrasil's own merge drivers to git (`jarl merge-driver flags --yg`). Without them nothing is sent. This is the only place Jarl touches another family tool. |
| Ratatoskr, Urd, Researcher | none; each installs, versions and releases on its own. |

The recommended install is the whole family together, but nothing forces it: Yggdrasil, Grain and Jarl each run without the others, and the 6.0.0 plan's D5 ("the family installs as a whole") is a recommendation, not a dependency. **Runes** is the family's shared code (relation extractors, the parser host and grammar recipe, the lock, the command table, the MCP adapter, the test kit, shared skill fragments): Grain and Jarl commit a pinned copy of the parts they use, and Yggdrasil installs `@chrisdudek/runes` at an exact version. It is infrastructure, not a member: nobody installs it to get work done, and it adds no edge.

**Shared contracts.** The machine documents the core exchanges are registered on one page: [Family Contracts](https://krzysztofdudek.github.io/Yggdrasil/family-contracts) (Yggdrasil's own `docs/family-contracts.md`), Jarl's two among them: the record library `jarl-record/4`, in the record's one format, and the loop profile `jarl-profile/1`. The add-ons carry no contracts of their own, so they get no row on that page. Who consumes which document, and which check covers it: [the contracts index](contracts.md).

**What is built and what is not yet.** The 6.1.0 release built the conditional trust mark in Jarl, advisory type law with ratification in Yggdrasil, and Jarl's ratification batch at close with its writes into Yggdrasil's logs. No tool in the family plans a whole task onto the graph before work starts: Horde did that, and it left the family on 2026-11-04 (below). The question of how much Horde added over a Jarl loop with a check was never measured, and the canon states no number for it.

## The register

Every public sentence about the family, on a README, a GitHub description, the profile or the website, follows the same register:

- **Plain words.** No jargon put on the reader. A term the reader has not met is either explained in the same sentence or left out.
- **Lead with the idea; let the tools be the evidence.** The thesis is that trust was the barrier and proof is the unlock. The tools show up as proof that it is being built, not as the pitch.
- **Lead with certainty, not with "no one has to read the code."** The promise is confidence that what ships is right; say that. "Proven, not read" is the mechanism underneath, not the pitch. Engineers and team leads bristle at anything that sounds like "skip the review", and they do not bristle at "provably correct". Frame the assurance gained, never the reading skipped.
- **Reading follows the risk.** Never say, anywhere, that the owner does not read code or never reads a diff, and never promise a reader that they won't have to. What he reads himself depends on the risk: anything that could do damage that can't be undone, or carry big consequences, he reads; the rest he checks through the proof his agents bring.
- **Show the real thing.** What actually gets done, and what is being aimed at. Building in public around a real thesis outlasts tutorial content.
- **Honesty is the brand.** Keep what is built today apart from where it is going, and say plainly which is which. In a space full of hype, a sentence that says "this part is not done yet" earns the exact trust the family is about.

## How the canon got here

The sections below record what changed in the canon and why, newest last. Each is history: the block above is what holds today.

### 6.0.0: Horde's family row

During 6.0.0 Horde dropped Agent Teams entirely: its README, its operating doc, its skill and its model reference were rewritten. Re-read on 2026-09-11, the body of Horde's README already carried the new shape (two recurring roles, director and worker, plus three one-shots, architect, legislate and retro, and the client, with the architect "Opus, no node of its own … approves or vetoes graph changes, rules the whole plan once"); "Agent Teams" had no remaining mention anywhere in the repository, and "5.9.0" survived only in its CHANGELOG, which is history. What that rewrite did **not** touch was Horde's own copy of the family section's table row. It still read "A steward, an owner per node, an architect with veto, workers and verifiers who never verify their own work, all held to the graph; nothing merges without two keys and an approval": the older organigram, sitting in the one place a reader skimming only the family table would see it. The canon's Horde row replaced it everywhere at once, and is now the single place that sentence is written.

### 6.1.0: Jarl joins the family, and D4 gets a second door

The 6.0.0 plan's D4, decided on 2026-09-09, made Horde the one door for any order, and the canon's map paragraph carried it as "Horde is the one door for any mission too big for one agent, not a second path that only opens once a lone agent runs out of room." Krzysztof changed D4 on 2026-09-16. Asked where Jarl stands against that rule, with three options (an add-on for work on a repository and no second path; a lighter door beside Horde, which changes D4; an internal tool kept out of the canon), he picked the second; his answer named the option, so the label is not his wording. From then the family had two doors: Horde for a mission held to Yggdrasil's law, and Jarl beside it, an issue loop with no law and no landing gate. The map paragraph replaced the one-door sentence with those two.

Jarl joined as the fourth add-on. It attached to the agent, depended on nothing in the family, and kept its own version number like Ratatoskr, Urd and Researcher. Horde did not use it inside its loop, so its row's last column said so instead of naming a role. The block, the versioning and the dependency notes named it, and the drift check read seven READMEs instead of six.

### Later in 6.1.0: Jarl moves into the core, the doors become pains, and a film prototype joins

The two-doors section above is history now; its framing is retired (list above). On 2026-09-27 Krzysztof set the direction. Krzysztof, 2026-09-27 (translated from Polish): "Then Yggdrasil, Grain and Jarl are the blocks, and Horde is the composer. Horde's architect would have Grain for measurements too." The accepted design of the whole family (the research folder `2026-09-27-family-vision-design`) turned it into rulings, and three of them change this canon:

- **Composition** (ruling `family-composition`). Krzysztof, 2026-09-27 (translated from Polish): "So the family is about programming: Yggdrasil, Grain, JarlSkill, Horde (skill). The add-ons are Ratatoskr, Urd, ResearcherSkill and a new one, a prototype [name omitted]." The core is Yggdrasil, Grain, Jarl and Horde, on one number; Jarl takes it from 6.1.0 (ruling `blocks-and-composer`, point 8). The add-ons were Ratatoskr, Urd, Researcher and the prototype, each on its own number. Runes is shared code, not a member.
- **Story** (ruling `entry-by-pain`). The opening sentence of the block is the one he chose, word for word. The adoption ladder ("Grain first", then Yggdrasil, then Horde) and the two doors gave way to a table of pains, because nobody outside had climbed any ladder yet; Grain is placed where it pays, right before law is written.
- **Trust and consent** (rulings `conditional-trust` and `consent-by-reach`). The check, where there is one, decides what lands in both tools, and a reviewer's word is testimony; law that reaches a whole type is proposed by the agent and admitted by the client in one batch.

Horde no longer runs beside Jarl but on it: a mission's record is a Jarl loop written through Jarl's record library, and Horde's architect always measures with Grain. So the dependency graph grew from two edges to five, all listed above, and Horde's requirement on Yggdrasil moved to 6.1.0 with Horde itself. The prototype (films of real running software, every claim traced to the product's logs) became the fourth add-on; it depended on nothing and Horde did not call it.

### 6.2.0: the film prototype leaves the family, and the canon points to Althing

Krzysztof, 2026-10-05 (translated from Polish): "Kick [it] out of the family. It was a prototype." (the ruling of that date that the prototype leaves the family). The film add-on that joined in 6.1.0 was a prototype and is no longer part of the family. The add-ons are three again: Ratatoskr, Urd and Researcher. The block, the versioning paragraph, the dependency table, the profile description and the retired-content list changed with it, and every family README, the profile and the GitHub descriptions followed the canon. Nothing in the family links to it, depends on it or releases it.

The same release moved the canon, with the rest of the family's layer, into Althing (ruling `althing-family-layer`), and the block gained one sentence at the end of its first paragraph: "The family is developed in the open in Althing: its releases, research and rulings." The owner chose to add it (ruling `ask-014`; he picked the option to add the sentence, a label, not his wording), and it reaches the seven READMEs after Althing's first push.
