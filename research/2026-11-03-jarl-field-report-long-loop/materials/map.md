# The field report, item by item, against Jarl at release/6.2.1

Each claim and request of `source.md` is checked against JarlSkill at release/6.2.1 (commit a1132a8). The report's loop ran Jarl 6.2.0. Between the tag v6.2.0 and release/6.2.1 only `README.md` and a social card changed (`git diff --stat v6.2.0..HEAD`), so every behaviour below is the same in both. Code references are in JarlSkill's `skills/jarl/scripts/` unless named otherwise. Behaviour was run with that tree's `jarl.mjs` on a scratch copy of `releases/6.2.0/.jarl`; the issues 529 to 532 named below were filed in that copy only.

Items that the report repeats in several places (Should change, Smaller, Backlog, the 18 sections, the 10 further items, the register) are one row each; the Source column names every place. Coverage was checked against every issue of the 6.2.1 loop and the Jarl-tagged issues of the 6.2.0 loop.

Columns: True at 6.2.1 (yes, partly, no), Covered (issue and how fully), Class (defect, gap, owner for a decision only the owner can take), Severity (what it costs a coordinator).

## Decisions only the owner can take

- **fr-03.** Whether done refuses while an acceptance line waits for the owner's sign-off. It changes the done gate.
- **fr-04.** Whether a later green check counts for the merges its commit contains. It changes what the landing banner promises.
- **fr-06, the second half.** Whether an approve relayed from a bot may clear an issue. It changes who may close.
- **fr-09.** Whether Jarl holds external requirement items and diffs them on re-import. It is a new concept.
- **fr-13.** Whether Jarl prints in the loop's language. It touches every surface.
- **fr-14.** Whether an exact-output comparison may stand in for a fresh review, inside the waiver of issue 004. It changes who may close.
- **fr-16.** Whether the reviewer's rank depends on the kind of work. It pulls against the rule recorded in issue 016.
- **fr-20.** Whether a commit after the approve spends it. It changes the done gate.
- **fr-25.** Whether a profile may require a visual verdict before a merge or done. It changes the gate.
- **fr-41.** Whether Jarl takes the register as a concept. It is the largest change the report asks for.
